## 3. 차별점

- 핵심: AI 사용법이 아니라 AI를 업무에 들여놓고 사고 없이 운영하는 법을 현업 눈높이로 가르친다
- 드문 조합: 개발 10년 + 서비스 운영·PO + 팀 운영·신규 인력 교육 + 지금도 매일 AI로 일하는 현역 학습자
- CISA는 자격으로만 표기 (감사자 활동 경험 없음 — "감사 시선" 표현 사용 안 함)
- 가르치는 대로 일한다: 강의 시스템과 도구가 곧 증거
- 강의를 고치는 구조가 있다: 검증 리포트와 개정 이력이 개선 역량의 물증
- 청중별 강한 이유: 규제 산업(보험) 서비스 운영 경험 / 비개발 입문자
- 사용하지 않음: CS실 실장 경험, 공부방 운영 (본인 결정)

## 4. 대표 주제: AI를 대하는 자세

- 전제: "상대가 바뀌었을 뿐, 일 맡기는 법은 이미 알고 있다" (출발점으로만 쓰고, AI가 사람과 다른 지점을 반드시 짚는다)
- 구조: AI의 성질(기초)이 자세의 이유가 된다

| AI의 성질 | 자세 | 시점 |
|---|---|---|
| 목적을 모르고 책임지지 않는다 | ① 주도권은 내가 | 시작 전 |
| 말해 준 것만 안다 | ② 시키기 전에 정리 | 시작 전 |
| 틀려도 확신 있게 말한다 | ③ 결과는 확인 | 진행 중 |
| 매번 새로 추측한다 | ④ 막히면 범위를 좁힌다 | 진행 중 |
| 기억하지 않는다 | ⑤ 다음을 위해 남긴다 | 끝난 뒤 |

- 강의 흐름: 현업 장면 → 막히는 지점 → 필요한 만큼의 기초 → 다시 장면 → "우리 팀이라면?"
- 손에 남는 것: 업무 지시서 1장, 확인표

- 어조 (11-05 결정): 가르치는 형태가 아니라 "나는 이렇게 AI를 대한다"를 소개하는 어조. AI에 끌려가지 않고 내가 리드하는 것이 핵심
- 비유 후보: 강아지 산책 — 강아지가 앞서가도 목줄을 쥔 주인이 방향을 정하고 언제든 되돌아갈 수 있다 (다른 사람의 비유이므로 강의에서 출처를 밝힘)
- 교안 작성은 급하지 않음. 강의에 쓸 경험을 더 찾는 중

## 14. 회차 실습 설계 확정 (2026-11-06 16시)

- 1회차(DX, 본인 스토리): 사람마다 정보 정리 방식이 다르다 → 폴더도 다르다 → 유통되며 통합이 어려워진다 → 핵심 인물 부재 시 멈춘다 → 최소 공통 기준만 합의 → 그 위에서 저장 도구 + LLM이 일상 언어로 찾아 준다. 실습: 같은 자료 다른 폴더 / 남의 폴더에서 찾기 / 정리 기준(정보조직론·SECI·PARA) / 도구 사다리 / AI 검색 전후 비교 / 업무 흐름도. 실무 원칙 6가지(원본 한 곳·링크 공유, 파일명 규칙, 폴더 3단계, 속성은 표의 열로, 메신저 결정은 당일 기록, 업무 카드)

- 본인 개념: 업무는 가로(처리→완료, 담당자·부서 건너)와 세로(보고·결재)가 모두 AX 되어야 정착
